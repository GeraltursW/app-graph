# 人工采集导入与游离区域并入：前端实施方案

日期：2026-09-15。本文为下一阶段实施设计，新增状态 API、自动并入、强制逐图分析尚未落地；本次代码变更是已有前端的模块化整理。

配套：[后端方案](20260915-orphan-merge-backend-plan.md)、[AI 契约](20260915-orphan-merge-ai-contract.md)、[模块重构说明](20260915-frontend-module-refactor.md)。

## 1. 入口与目录

保持现有蓝白、Vben Admin 风格与 Ant Design Vue 组件。首屏右侧保留项目基线、人工采集导入、批量并入、建设日报，不新增一排重复入口。

| 模块 | 职责 |
| --- | --- |
| capture-import/ | 上传、任务列表、图片分析、Excel 记录复核、预检提交；接口在 capture.api.ts |
| orphans/ | 已入库游离区域的父节点确认、批量接入、真实入口登记；接口在 orphan.api.ts |
| graph/ | 主树、G6、页面详情；正式提交后的刷新与定位 |
| coverage-report/ | URL 覆盖事实与日报，区分已覆盖和主树可达 |
| shared/ | 请求基础配置、S3 图片与公共 UI，不包含并入业务规则 |

index.vue 只编排当前 APP、选中节点和跨模块刷新。新增上传任务、复核草稿状态放在 capture-import 内；不要再写回根目录大 API 文件。

人工采集导入负责“外部证据变成可信页面和关系”；批量并入负责“已有游离子图补上可信入口边”。两者调用同一套后端并入校验规则，但不混淆对象和状态。

## 2. 当前实现与改造点

| 当前实现 | 目标 |
| --- | --- |
| 20 MiB 前端限制，普通请求上传 | 保留当前上限，后端流式完成后共同升级到 100 MiB |
| useAi 可选、不可用时禁用 | 显示强制分析策略；不可用时说明等待/重试，不提供绕过 |
| 每 2 秒拉完整详情 | 轻量 status + revision，改变后再拉当前分页 |
| 本地草稿、刷新会重建 | 服务端保存草稿，recordRevision 乐观锁 |
| 人工选择后统一提交 | 满足规则自动并入，例外集中人工确认 |
| READY 完成解析 | 展示图片分析、待确认、已保存、主树可达等独立统计 |

本次不宣称已经新增这些界面与接口；实施时按文末 P0/P1/P2 分批交付。

## 3. 上传体验

上传前显示接受的 ZIP/Excel 模板、文件大小、最大行数、图片规则以及 APP。统一使用后端实际约定的限制，禁止前端展示 100 MiB 而服务端仍限制 20 MiB。

首次上传由用户确认一次 AUTO_VALIDATED 策略：明确父节点且证据/目标/图谱校验通过的记录允许自动并入；不明确项留待复核。不要要求对每一行再点一次“允许 AI”。

进度分两个区域：

1. 文件上传：Axios onUploadProgress 字节百分比。达到 100% 后显示“服务端正在接收并校验”，直到取得 jobId；不能提前显示成功。
2. 后台任务：QUEUED、解包、逐图分析、候选匹配、自动并入、待确认/完成；分别显示计数，不能把解析 100% 误认为并入完成。

接口返回 202 + jobId 后允许关闭抽屉。关闭不取消后端任务，重新打开按 APP 查询任务列表即可恢复。当前没有断点续传，连接中断要明确提示重新上传；不能把异步解析宣传成分片续传。

上传按钮请求期间禁用重复提交，但输入和页面导航仍可用。请求 clientRequestId 与包摘要共同做服务端幂等；响应丢失后先查任务，不盲目生成另一任务。

现有 HTTP 封装默认超时较短，实施时需贯通 timeout 和 onUploadProgress 配置到真实 Axios 请求。建议上传独立 180 秒可配置，状态查询维持短超时；只改组件传参而封装不透传不会生效。

## 4. 任务面板

采用 Ant Design Vue Table 展示任务，可按 APP、处理状态和创建时间筛选。任务详情分“记录”“图片”“提交历史”三个页签，不把所有截图一次性展开到 DOM。

建议摘要：记录总数、图片总数、分析成功/缓存命中/失败、自动并入、待确认、已保存待接入、主树可达。

图片状态计数必须互斥，缓存命中不要同时重复记入成功数。记录与图片是不同分母，一张图可对应多条记录。

| 情况 | 显示与操作 |
| --- | --- |
| AI 服务暂不可用 | 任务保留，说明原因，允许重试失败分析 |
| 部分图片失败 | 标记依赖它的记录，不阻塞其他独立组 |
| 未被 Excel 引用的图片 | 图片页签可见分析结果，可关联记录，不自动建页 |
| 解析有错误行 | 行级错误可定位，任务 READY 不显示“全部成功” |
| 自动合入完成 | 查看每条新增页/边、时间、规则版本与定位入口 |

图片缩略图懒加载；全屏预览可切换同记录目标/父页/控件证据，图片 URL 沿用 shared/image.api.ts 的 S3 规则，不直接拼存储路径。

## 5. 轮询与一致性

使用 GET /captureImports/{jobId}/status，每 2 秒一次且不允许请求重叠；后台页签可降低频率。revision 改变后才拉当前需要的 records/assets 分页。

关闭抽屉或切换 APP 时停止旧订阅/轮询；请求序号或 AbortController 防止上一 APP 的响应覆盖当前页面。组件卸载清理定时器。

网络错误退避重试并显示“状态暂未更新”，保留已有数据；不要像当前方案一样首次错误后永久停止。DONE/FAILED 等终态停止轮询，人工重试任务后恢复。

轮询更新服务器状态，不覆盖未提交编辑内容。草稿保存携带 recordRevision，冲突时展示差异供用户选择，不能静默使用最后写入值覆盖另一位同事的确认。

SSE 是后续增强，不是 P0 前置条件。即使接入 SSE，也保留状态查询用于断线重连和页面恢复。

## 6. 父节点确认

记录表显示目标 URL/截图、父节点证据、AI 状态、阻塞原因和处理结果。复核时用 Drawer 或 Modal 对照目标截图、父截图、控件截图和候选节点，避免挤压主图。

| 输入 | 处理 |
| --- | --- |
| 明确有效 parentPageId，所有校验通过 | 自动并入并显示审计结果 |
| 只有 parentUrl | 列出候选，显示同 URL 的不同功能页面，人工确认真实父页 |
| 提供多个互相冲突的父字段 | 显示冲突，不悄悄选最高分 |
| previousRecordId | 展示包内前序依赖，提交按依赖组校验 |
| 没有父节点 | 搜索主图、选择候选或保留新区域 |
| 全新独立入口 | 走真实入口登记，提交入口类型和证据，不挂假 root |

候选可按标题、URL、embeddingText 检索；显示命中证据而非只显示 AI 分数。图上定位后高亮目标与邻居，可返回当前草稿，不丢已填字段。

批量设置同一父节点只适用于用户确认这些记录确实共享入口的情况。提交前逐条验证目标身份、控件和环路；不能把“批量”解释成跳过证据。

对未知区域 B→C→D，保留内部关系。后续只需确认 A→B；成功后后端回传 B/C/D 可达状态，前端一起更新，无需重复拖拽三次。

## 7. 预检与提交

提交路径：保存复核草稿 -> 请求 precheck -> 显示可提交组和冲突 -> 二次确认 -> commit -> 查询最终结果 -> 刷新图谱和覆盖摘要。

预检带选中 recordIds、处理模式与 revision；服务端返回 planId、graphVersion、analysisRevision、依赖组和阻塞原因。预检成功后图谱仍可能被别人修改，commit 必须重新检查。

同一次确认的 requestId 固定，与完整 payload 对应。提交超时先查 commits，再用同一个 requestId 重试；内容变了才生成新 requestId。提交按钮 loading，不重复派发。

409 显示“图谱或复核信息已更新，请重新预检”，保留草稿并刷新差异。失败不清空选中行；独立组部分成功时仅把已确认提交的项标为完成。

自动提交与人工提交共用结果呈现。自动提交不能绕过后端校验，也不能使用前端定时器作为可靠后台执行器。

## 8. 如何确认游离节点完成使命

不要只显示一个“成功”标签。至少区分：

- 图片已分析：证据已处理，但可能未入库。
- 页面已保存：有真实 pageId，可能仍是游离节点。
- URL 已覆盖：后端已记录该 APP/URL 的覆盖事实。
- 已接入主树：从确认入口可达，reachable=true。

只有最后一种状态才能从待接入列表移除。收到成功响应后重新拉后端图谱，不依据本地猜测删除游离项。

成功提示示例：“已保存 12 个页面，其中 9 个已接入主树，3 个保留为新区域”。旁边提供“定位新并入区域”，不自动把 12 个页面都算作合入。

同 URL 补图不改变 firstCoverageTime。建设日报读取后端实时覆盖事实；主树接入变化与 URL 新增覆盖分别统计，不维护另一份本地 Excel 账本。

## 9. 审计、撤销与权限预留

提交历史展示操作人、AI/人工来源、规则版本、新增页面/图片/边、阻塞项与提交结果。没有认证时明确显示“本地操作/未认证”，不能伪造真实审核人。

当前游离批量并入已有受版本约束的回滚，但不等于人工采集上传链路的所有写入均可撤销。新链路的撤销须单独定义：仅删除该提交新增且未被后续依赖的边，保留旧节点、旧边与历史覆盖事实。

后续加入权限时，区分上传、复核、确认真实入口和撤销；本阶段无需强行改登录系统，但审计字段应提前保留。

## 10. 交付顺序与验收

P0：保留 20 MiB，接强制 AI、轻量状态 API、图片列表与失败重试、服务端草稿。AI 服务故障必须可恢复。

P1：明确父节点自动并入、异常集中复核、预检/提交、一组补入口使整个区域接通、刷新定位和审计。

P2：后端完成流式与压测后同步提升 100 MiB；SSE、向量候选和 HDC 验证增强。

验收至少包括：

1. 上传进度到 100% 后仍能看到解析/分析过程；关抽屉重开恢复任务。
2. 图片多于 Excel 行时每张都有分析状态；未引用图可见，失败只阻断相关组。
3. 有合法明确父节点自动并入；父 URL 多候选不自动选；无父节点不挂 root。
4. 其他同事改图后旧计划返回 409；重新预检不丢人工草稿。
5. 网络响应丢失重试不重复生成页面/边；切 APP 不串数据。
6. 新增区域和共享目标不覆盖既有结构；形成环的边被服务端拒绝。
7. 合入后树、画布、游离列表、详情和覆盖摘要一致；同 URL 换图首次覆盖不变。
8. 单独保留 Mock 演示数据与真实接口测试报告，不能用 Mock 通过替代后端可落地验收。

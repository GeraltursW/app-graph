## 已实现

## 使用步骤

1. 选择 APP，打开「批量并入」。工作台展示未从真实入口可达的区域，不是简单把所有入度为零的节点当首页。
2. 找得到入口的区域：勾选、选父节点、填控件、确认并入。查看待接入数量减少；需要时撤销最近批次。
3. 完全新区域：通过「入口归类」填写待确认原因；确有独立唤起方式时才登记真实入口及证据。
4. 打开「建设日报」的「基准维护」，填写分组、总量和每行一条高频 URL，二次确认发布。
5. 选择已结束的早/晚报区间生成报告，点击 APP 名称查看 URL 明细，点击定位返回画布。

URL 覆盖与结构接入是两件事。存在非空 AI 归类的游离截图可以已覆盖该 URL，但仍没有可靠执行路径；URL 占位符则不计覆盖。日报「游离 URL」列采用覆盖缺口口径，工作台「待接入」采用结构可达口径，两者不要求相等。

## 数据口径

- APP + 原始完整 URL 精确区分；不合并大小写、参数或不同 APP 下的同名 URL。
- 任一关联页面实例拥有非空 `embedding_text` 时登记覆盖事实。URL 相同、更换图片、重复上传或重新关联节点，不重写首次时间。
- 历史已有覆盖仅登记基线，首次时间为 NULL；不能把迁移时间当作历史首次发现时间。
- 事实账本不会随截图或节点删除清空；当前覆盖数按生成时现存实例计算，再出现同 URL 也不会重新计作新增。
- 北京时间：早报 `[昨日20:00, 今日08:00)`；晚报 `[今日08:00, 今日20:00)`，不允许生成未结束区间。
- 新增数来自上述区间的首次事实；存量统计是生成时的数据库快照，补生成历史日期不会重建当时的全部存量。
- 报告保存生成时间及基准版本；生成之后不随图谱编辑实时变化。基准维护即时生效于后续报告，而非改写旧报告。
- 全量覆盖率按有效分母聚合，并按单 APP 总量封顶；缺失/零分母显示 `—`，去 0 口径排除已覆盖数为 0 的 APP。

## 运行与源码

```powershell
cd D:\codes\app-graph
npm install
npm run dev:mock -- --port 5177 --strictPort
```

演示入口 `http://127.0.0.1:5177/`，不需要后端。Mock 为内存数据，刷新页面后修改和报告不持久化；演示首次时间只用于展示，不用于真实统计。Mock 不模拟数据库并发和持久化保障。

联调：在本地 `.env.local` 设置 `VITE_USE_MOCK=false`、`APP_GRAPH_PROXY_TARGET=http://127.0.0.1:8080`，重启 Vite。API 前缀默认为 `/appGraph`。不要把真实访问凭据提交到 Git。

- `src/views/app-graph/components/GovernanceWorkspace.vue`：工作台与日报编排。
- `src/views/app-graph/components/CoverageTrend.vue`：周期趋势。
- `src/views/app-graph/governance.api.ts`：真实/Mock 请求边界。
- `src/mock/coverageReports.ts`、`src/mock/appGraph.ts`：无后端演示。
- `tests/graph-governance.test.js`：DAG 去重、独立控件关系、实际归类字段测试。

## 验收与边界

前端生产构建、`vue-tsc` 和 3 项 Node 测试通过。浏览器走通日报生成、基准 v1→v2 发布（旧报告仍 v1）、父节点搜索、并入后回查与撤销；另验证 Java HTTP 查询和报告生成。后端数据库验证使用独立 PostgreSQL，不是生产库。

尚未实现：pgvector 候选召回、AI 置信度自动并入、HDC 在线验证入口、自动定时生成、全历史状态重建、生产单表适配、独立逐边编辑器。候选目前只使用明确的 `previousPageId` 采集证据并要求人工核对，不能称为已完成 AI 自动归并。多父节点的旧拖拽修改被后端拒绝，以免一次删除多个入口；需要逐边编辑的下一步改造。

HTML 导出目前是数据汇总和 URL 明细，不含 ECharts 图像。历史选择器每个日期/早晚类型显示最近一次生成结果，最多 60 条；旧快照仍留在后端，可凭报告 ID 查询。
